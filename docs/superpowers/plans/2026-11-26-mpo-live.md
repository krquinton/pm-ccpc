# MPO LIVE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, user approved through build).

**Goal:** Livestream screen `mpolive.html` (5 views) + backend `mpolive-setup.html` for the MPO Cup per-category pool draw.
**Architecture:** Static HTML + Firebase RTDB compat (mindoropickleballorg) under `mpolive/`. Sponsors and draw are same-origin iframes; draw is a patched copy of the tested randomizer.
**Tech Stack:** HTML/CSS/vanilla JS, Firebase 10.12.2 compat (app + database), GSAP/confetti (draw only).
**Spec:** `docs/superpowers/specs/2026-11-26-mpo-live-design.md`

## Global Constraints
- Folder: `pm-ccpc/MPO LIVE/`. Do not edit `mpocup/apps/randomizer/*` or `pm-ccpc/mpo-sponsors.html`.
- All data under RTDB `mpolive/` (never `mpo/`).
- Views ids: `countdown, sponsors, draw, schedule, format` (keys 1–5).
- Default countdown text "Draw Assignment will commence in", default 5 minutes, done text "Draw is starting now".
- Seed schedule/format rows exactly as the user listed them.

## Review Focus
1. Setup opened before any data exists → seeds defaults, screen shows defaults (not blank/errors).
2. Countdown end time computed with `.info/serverTimeOffset` so setup and screen PCs agree.
3. Clicking a view on screen while setup also changes it → last write wins, both UIs reflect it.
4. "Draw this category" pressed while the draw iframe is not connected → setup warns, does not fire.
5. Starting the next category's draw must not erase the previous bucket's saved result.
